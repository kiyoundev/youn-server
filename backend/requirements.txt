# binary (baked into backend/Dockerfile's FROM tag) need to be compatible.
# An open range let pip silently resolve a newer client than the image's
# Chromium build on an unrelated rebuild, twice in one session (#15).
#
# Note: mcr.microsoft.com only publishes per-MINOR-version jammy tags
# (v1.61.0-jammy, v1.62.0-jammy — confirmed via the registry's tag list,
# no v1.62.1-jammy exists), while PyPI only has patchright's per-PATCH
# releases (1.61.1, 1.61.2, 1.62.1 — no 1.61.0 or 1.62.0 exists on PyPI
# either). An exact version-string match is impossible by construction —
# pin the newest patch (1.62.1) against the newest same-minor-line image
# (v1.62.0-jammy in the Dockerfile), since patch releases normally don't
# change the underlying Chromium build, only minor/major ones do.
